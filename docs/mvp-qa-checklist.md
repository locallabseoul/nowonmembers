# 노원멤버스 MVP QA 체크리스트

## 계정 준비
- Supabase Auth에서 가게, 크리에이터, 관리자 테스트 계정을 각각 만든다.
- 로컬 테스트에서는 `.env.local`의 `NEXT_PUBLIC_SITE_URL`을 `http://localhost:3003`으로 맞춘다.
- Supabase Dashboard의 Auth URL Configuration에서 Redirect URLs에 `http://localhost:3003/auth/callback`을 허용한다.
- 최초 관리자 계정은 Supabase SQL Editor에서 아래 쿼리로 지정한다.

```sql
update public.profiles
set role = 'admin', status = 'active'
where email = '관리자이메일@example.com';
```

- 포인트 결제를 확인하려면 `.env.local`에 `NEXT_PUBLIC_TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`, `SUPABASE_SERVICE_ROLE_KEY`가 모두 있어야 한다. 결제 승인과 환불은 서버 전용 키를 쓴다.
- 주소 검색과 캠페인 상세 지도를 확인하려면 `NAVER_MAPS_CLIENT_ID`, `NAVER_MAPS_CLIENT_SECRET`이 필요하다. 없으면 오류 없이 조용히 실패한다.
- 결제는 반드시 **토스페이먼츠 테스트 키**로 확인한다. 실키로 테스트하면 실제 매출과 환불이 발생한다.

## 핵심 운영 흐름
- 가게 계정으로 로그인한 뒤 `/business/dashboard`에서 가게 프로필을 저장한다.
- `/business/campaigns/new`에서 캠페인을 만들고 상태가 `in_review`로 저장되는지 확인한다.
- 관리자 계정으로 `/admin`에 접속해 캠페인을 승인하고 공개 목록에 노출되는지 확인한다.
- 크리에이터 계정으로 `/creator/profile`을 저장한 뒤 공개 캠페인에 지원한다.
- 관리자가 지원자를 `recommended`로 표시한다.
- 가게가 `/business/dashboard`에서 추천 지원자를 최종 선정해 협업을 생성한다.
- 크리에이터가 `/creator/dashboard`에서 콘텐츠 URL을 제출한다.
- 관리자가 제출물을 승인한 뒤 로컬 스토리로 발행한다.
- `/stories`에서 발행된 로컬 스토리가 공개되는지 확인한다.

## 포인트 충전과 결제
- `/business/points`에서 충전 옵션 3종이 아래대로 표시되는지 확인한다.
  - 25,000P / 결제 27,500원 / 보너스 없음
  - 50,000P + 보너스 5,000P / 결제 55,000원
  - 100,000P + 보너스 10,000P / 결제 110,000원
- **동의 체크박스를 켜기 전에는 결제 버튼이 비활성화**되는지 확인한다.
- 충전 금액을 바꾸면 고지 박스의 결제금액, 공급가, 부가세, 지급 포인트가 함께 바뀌는지 확인한다.
- 결제를 완료하면 지갑의 `사용 가능`이 유상 포인트와 보너스를 더한 만큼 늘고, 이용 내역에 `포인트 충전`과 `충전 보너스`가 각각 남는지 확인한다.
- 결제 내역의 `지급 포인트`가 보너스를 포함한 값으로, `결제금액`이 부가세 포함 금액으로 표시되는지 확인한다.
- 결제창을 그냥 닫으면 주문이 `결제 실패`로 남고 포인트는 늘지 않아야 한다.
- 카드사 승인을 거절시키면 `/business/points/fail`로 이동하고 주문이 `결제 실패`가 되는지 확인한다.
- 결제 완료 화면을 새로고침해도 포인트가 두 번 적립되지 않아야 한다. 주문번호 기준으로 멱등 처리된다.

## 캠페인 포인트 예약
- 캠페인 검수 제출 시 모집 정원 1명당 5,000P가 예약되고 `예약 중`으로 잡히는지 확인한다.
- **포인트가 부족한 상태로 검수를 제출**하면 `/business/points`로 이동하며 필요 포인트와 부족 포인트가 안내되는지 확인한다.
- 그 화면에서 충전을 마치면 저장해 둔 캠페인이 **자동으로 다시 검수 제출**되고 대시보드로 이동하는지 확인한다.
- 관리자가 예약 없는 캠페인을 승인하려 하면 `활성 포인트 예약이 없는 캠페인은 승인할 수 없습니다.` 오류로 막히는지 확인한다. `/admin` 목록에는 `예약 없음` 배지가 뜬다.
- 공개 전 캠페인을 취소하면 예약 포인트가 전액 반환되고 이용 내역에 `예약 반환`이 남는지 확인한다.
- 관리자가 캠페인을 반려해도 예약 포인트가 반환되는지 확인한다.

## 모집 마감 정산
- 정산은 모집 마감일 다음 날(한국 시간 기준)에 처리된다. **자동 스케줄러가 없어** 캠페인 목록·상세, 가게 대시보드, 관리자 화면 중 하나를 열어야 실행된다.
- 정원보다 유효 신청자가 적은 경우: 부족한 인원만큼 예약 포인트가 반환되고 캠페인이 `selecting`이 되는지 확인한다.
  - 예) 5명 모집(25,000P 예약), 3명 지원 → 15,000P 소비, 10,000P 반환
- 유효 신청자가 0명인 경우: 예약 포인트가 전액 반환되고 캠페인이 `failed`가 되는지 확인한다.
- 유효 신청자가 정원 이상인데 가게가 일부만 선정한 경우: **반환이 없어야 한다.**
- 이용 내역에 `캠페인 정산`이 남고 `/admin`의 배지가 `예약`에서 `확정`으로 바뀌는지 확인한다.

## 환불과 만료
- 결제 내역에서 환불하면 **남은 유상 포인트 전액**이 원결제수단으로 환불된다. 부분 환불은 지원하지 않는다.
- 환불 금액이 남은 포인트에 부가세 10%를 더한 값인지 확인한다. 예) 잔여 25,000P → 27,500원
- 환불하면 같은 결제에 연결된 **미사용 충전 보너스가 회수**되고 이용 내역에 `환불 보너스 회수`가 남는지 확인한다.
- 캠페인에 예약된 포인트는 환불되지 않아야 한다. 잔여 유상 포인트가 없으면 `환불 가능 잔액 없음`으로 표시된다.
- 충전 보너스가 캠페인에 예약된 상태에서는 환불이 거부되는지 확인한다.
- 유효기간은 유상 포인트 5년, 충전 보너스 1년이다. 지갑 카드의 `다음 만료` 날짜가 각각 맞는지 확인한다.
- 만료 처리도 **자동 스케줄러가 없다.** 해당 가게가 `/business/points`를 열거나 캠페인을 제출·환불할 때 정리된다.

## 관리자 포인트 운영
- `/admin`에서 가게 포인트를 조정할 수 있다. 5,000P 단위, 절대값 500,000P 이하, 사유 필수이며 0은 입력할 수 없다.
- 조정 후 이용 내역에 `운영자 지급` 또는 `운영자 차감`이 사유와 함께 남는지 확인한다.

## 접근 권한
- 크리에이터 계정으로 `/business/points`, `/business/dashboard`에 접근하면 자신의 대시보드로 되돌아가는지 확인한다.
- 로그아웃 상태에서 `/api/maps/geocode?query=노원구`를 직접 호출하면 403이 나와야 한다.
- 가게 계정으로 로그인한 상태에서는 프로필과 캠페인 생성 화면의 **주소 검색이 정상 동작**해야 한다.
- 로그인 후 오래 두었다가(액세스 토큰 만료 이후) 페이지를 새로고침해도 로그아웃되지 않는지 확인한다.

## 화면 확인
- 홈, 캠페인 목록, 캠페인 상세, 지원 폼, 가게 대시보드, 크리에이터 대시보드, 관리자 화면, 포인트 화면을 모바일과 데스크톱 폭에서 확인한다.
- **모바일 폭에서 헤더 햄버거 메뉴**로 캠페인과 노원스토리에 갈 수 있는지 확인한다. 가게 계정이면 `캠페인 만들기`도 메뉴에 있어야 한다.
- 없는 주소(`/does-not-exist`)로 접속하면 404 안내 화면이 나오는지 확인한다.
- 푸터와 `/terms` 제11조에 사업자 정보와 통신판매업신고번호가 표시되는지 확인한다.
- 카카오톡이나 슬랙에 사이트 링크를 붙여 공유 카드 이미지가 나오는지 확인한다.
- 버튼 클릭 후 오류가 있으면 URL의 `error` 파라미터와 Supabase Table Editor의 행 상태를 함께 확인한다.
