노원멤버스 주민 앱 · 화면 설계서
v0.1 · 2026.11.12 · 검토용
목적: 주민이 가게를 발견하고 쿠폰을 사용한 뒤 단골로 저장하는 경험을 구체화한다. 이 문서는 구현 기준 초안이다. 화면 시안은 실제 계정·DB에 연결되지 않으며, 모든 가게·혜택·코스는 가상 예시다.
1. 검토 자료와 사용 방법
프로젝트 기준 문서: https://docs.google.com/document/d/1KPQUHbd-FPt3s_kqI_KWtmlM0TbBUO_rtgP1encXF9c
6개 화면 이미지: https://drive.google.com/file/d/1tL9cjtfv45oSN9Zp_21mJq09SsrNNOiz/view
클릭형 시안: https://drive.google.com/file/d/1CyMrUlfC6bLT_RVK_o8EI8PUH1DnacTv/view
HTML 시안은 Drive에서 내려받아 브라우저로 연다. ‘핵심 흐름 체험’ → ‘가게 보기’ → ‘쿠폰 받기’ → ‘로그인 상태 체험하기’ → ‘매장에서 사용하기’ 순서로 확인한다. 체험용 코드는 123456이다. 실제 인증·발급·사용은 일어나지 않으며 새로고침하면 초기화된다.
‘6개 화면 한눈에’에서는 전체 구성을 비교한다. ‘처음부터 체험’에서는 동네 선택부터 시작한다. 보조 화면으로 동네지도와 혜택을 포함했으며, 지도는 가상 배치이다. 동네를 바꿔도 예시 콘텐츠는 공릉동으로 유지된다.
2. 이번 설계의 기준
정보 구조: 하단 탭은 오늘 / 동네지도 / 혜택 / 마이. 관심 동네는 첫 진입 화면이며, 가게·코스 상세와 쿠폰 사용 화면은 각 목록에서 진입한다.
탐색과 로그인: 공개 가게·코스·혜택은 로그인 없이 탐색한다. 쿠폰 발급, 단골·코스 저장, 개인 쿠폰함은 로그인 후 이용한다. 인증이 끝나면 원래 화면과 요청한 행동으로 돌아간다. 로그인 취소 시 탐색 화면과 입력 상태를 유지한다.
브랜드: 기존 초록 계열을 유지하고 주민용 시안에는 여백과 큰 제목, 따뜻한 중립색을 사용한다. 본문과 주요 버튼에는 충분한 대비를 확보하는 짙은 녹색을 쓴다. 밝은 초록은 강조와 장식에 제한한다.
콘텐츠: 첫 버전 추천은 운영자가 선정한다. 실제 근거가 없는 거리·현재 영업 여부·인기 순위·리뷰 수는 표시하지 않는다. ‘오늘’의 추천은 실시간 영업 보증이 아니다. 협찬·광고 콘텐츠는 표시 기준을 정해 구분한다.
범위: 스탬프, 주민 채팅, 모임, 결제는 이 설계에 포함하지 않는다. 출시 플랫폼·앱 기술·지도 공급자·푸시 도입 시점은 별도 결정한다.
3. 주요 이용 흐름
처음 방문: 관심 동네 선택 → 오늘 → 가게 또는 코스 상세. 동네 선택을 건너뛰면 노원 전체를 탐색한다. 초기 추천 동네는 운영 설정으로 정하고 거주지를 추정하지 않는다.
쿠폰 사용: 오늘 → 가게 상세 → 조건 확인 → 쿠폰 받기 → 필요 시 로그인 → 발급 성공 → 내 쿠폰 → 매장 직원 코드 입력 → 서버 확인 → 사용 완료.
단골 저장: 가게 상세 → 단골 저장 → 필요 시 로그인 → 저장 성공 → 마이에서 확인. 코스 저장도 같은 흐름을 따른다.
재방문: 마이 → 저장한 가게·코스 → 최신 혜택 확인. 가게나 코스가 비공개·종료된 경우 이유를 표시하고 목록에서 제거할 수 있게 한다.
4. S01 · 관심 동네 선택
목적과 진입: 첫 방문자가 탐색할 생활권을 정한다. 첫 실행 또는 오늘·마이의 동네 변경 버튼에서 진입한다.
위에서 아래 순서: 브랜드 → ‘어느 동네부터 둘러볼까요?’ → 동네 선택 버튼 → 서비스 안내 → ‘선택한 동네 둘러보기’ → ‘동네 선택은 나중에 할게요’. 시안에서는 공릉동을 예시로 선택해 두었다.
동작: 동네는 우선 하나를 선택한다. 선택 상태를 테두리와 텍스트로 함께 표시한다. 둘러보기 버튼은 오늘로 이동하며 선택값을 반영한다. 건너뛰기는 노원 전체로 이동한다. 위치 권한을 필수로 요청하지 않는다.
데이터: 동네 식별자·표시명·노출 순서를 관리한다. 비로그인은 기기에 선택값을 저장하고, 로그인 후 계정 설정과 동기화하는 정책을 정한다. 동 단위와 행정동 단위의 매핑은 데이터 설계 단계에서 확정한다.
예외와 완료 기준: 선택 지역의 등록 정보가 없으면 ‘아직 이 동네의 가게를 준비 중이에요’와 전체 보기 제공. 실패한 원격 저장은 재시도 안내하고 선택값은 보존. 위치 권한 없이 탐색을 시작할 수 있어야 한다.
5. S02 · 오늘
목적과 진입: 홈 탭에서 가볼 만한 장소를 발견한다. 선택한 동네를 상단에 항상 보여준다.
위에서 아래 순서: 브랜드·동네 변경 → 짧은 인사·핵심 문구 → 대표 코스 카드 → ‘코스 둘러보기’ → 오늘 들러볼 가게 → 혜택 요약 → 하단 탭.
동작: 코스 카드는 S04, 가게 카드는 S03으로 이동한다. 동네 변경은 S01로 이동하며 돌아오면 목록을 갱신한다. 하단 혜택 탭은 쿠폰 발견 목록, 마이 탭은 S06으로 이동한다. 뒤로 돌아오면 목록의 스크롤 위치를 보존한다.
데이터: 공개 가게의 이름·소개·대표 이미지, 승인·공개된 콘텐츠, 발급 가능한 쿠폰 요약, 운영자가 선택한 추천 코스. 발급 가능 여부는 쿠폰 승인·기간·남은 수량·코드 설정 상태를 함께 판단한다.
예외와 완료 기준: 로딩은 카드 골격 표시. 이미지가 없으면 기본 이미지 사용. 콘텐츠가 비었으면 전체 동네 보기 제공. 조회 실패는 재시도 제공. 발급 종료 혜택이 추천 카드에 남지 않도록 갱신한다.
6. S03 · 가게 상세
목적과 진입: 가게 방문 여부를 판단하고 혜택을 받거나 단골로 저장한다. 오늘·지도·코스·마이에서 진입한다.
위에서 아래 순서: 뒤로·단골 저장 → 대표 이미지 → 동네·업종 → 가게명·소개 → 혜택과 사용 조건 → 위치·지도 → 확인 가능한 영업 정보 → 하단 고정 쿠폰 버튼.
쿠폰 버튼 상태: 미발급은 ‘쿠폰 받기’, 이미 발급은 ‘받은 쿠폰 보기’, 사용 완료는 ‘사용 내역 보기’. 미발급자가 발급 불가 상태이면 ‘발급 종료’ 등 이유를 표시하고 비활성화한다. 유효 쿠폰이 없으면 쿠폰 버튼을 숨기고 가게 탐색은 유지한다. 복수 쿠폰은 목록에서 하나를 선택하도록 한다.
단골 저장: 비로그인은 인증 후 원래 행동을 이어간다. 저장 성공 후 ‘저장됨’ 표시 및 마이에 반영. 실패 시 이전 상태로 돌리고 안내한다. 저장 해제는 동일 버튼으로 처리한다.
데이터: 공개용 가게 프로필·주소·소개·이미지와 쿠폰 공개 정보. 관리자 메모·사용 코드·비공개 연락처는 주민 응답에 포함하지 않는다. 위치 좌표가 없으면 주소만 표시하고 잘못된 지도 핀은 만들지 않는다.
예외와 완료 기준: 발급 버튼을 누르는 사이 수량이 소진되면 ‘방금 쿠폰이 모두 소진됐어요’와 다른 혜택 보기 제공. 중복 탭을 잠그고 서버 결과를 기준으로 발급 내역을 갱신한다. 기간·조건은 받기 전에 확인 가능해야 한다.
7. S04 · 코스 상세
목적과 진입: 여러 장소를 연결한 짧은 외출 계획을 확인하고 저장한다. 오늘 또는 마이에서 진입한다.
위에서 아래 순서: 뒤로·코스 저장 → 제목·소개 → 지역·장소 수·예상 시간 → 순서별 장소·설명 → 관련 가게·혜택 연결 → 하단 저장 버튼.
동작: 연결된 참여 가게는 S03으로 이동한다. 일반 산책 장소 등 가게가 아닌 장소는 장소 설명과 위치 정보를 제공한다. 운영자가 정한 순서대로 보여주되 길안내·자동 경로 최적화는 첫 버전에서 제공하지 않는다.
데이터: 코스 제목·소개·대표 이미지·지역·공개 상태·갱신일, 장소별 순서·설명·위치·예상 체류시간·선택적 가게 연결. 약 2시간은 예시 기준 체류 105분과 이동 15분을 더한 값이며 확정 일정이 아니다.
예외와 완료 기준: 장소가 휴업·비공개가 되면 해당 항목을 표시하고 운영자에게 갱신 대상으로 전달한다. 연결 가게가 없어도 코스의 일반 장소를 표현할 수 있어야 한다. 코스 저장과 저장 해제가 마이에 일관되게 반영되어야 한다.
8. S05 · 내 쿠폰과 사용
목적과 진입: 발급된 쿠폰의 상태를 확인하고 매장에서 사용한다. 발급 성공 직후, 혜택의 내 쿠폰함, 마이에서 진입한다. 실제 서비스에서는 발급 전 쿠폰을 내 쿠폰함에 표시하지 않는다. 시안의 발급 전 카드는 구성 미리보기이다.
위에서 아래 순서: 제목 → 사용 가능·지난 쿠폰 분류 → 상태·가게명·혜택·기간·조건 → ‘매장에서 사용하기’ → 직원 입력 안내. 지난 쿠폰은 사용 완료·만료·발급 취소를 텍스트로 구분한다. 시안의 ‘상태별 안내’는 설명용 표시다.
사용 동작: 버튼을 누르면 가게명·혜택을 다시 보여주는 직원 코드 입력 창을 연다. 숫자 6자리 입력 후 ‘확인하고 사용 완료’를 누른다. 서버 성공 응답 후에만 사용 완료로 변경하고 사용 시각·가게·혜택을 보여준다. 창을 닫는 것만으로 사용 처리하지 않는다.
코드 오류: 기존 구현은 5회 실패 시 10분 잠금을 적용한다. 앱에서는 서버가 반환한 잠금 종료 시각을 기준으로 안내하고 입력을 막는다. 코드 원문은 앱으로 내려받거나 저장하지 않는다. 시안의 123456은 체험 전용이며 잠금·서버 검증은 구현하지 않았다.
상태 처리: 사용 전 기간이면 ‘사용 시작 전’, 만료면 ‘기간 만료’, 취소면 ‘발급 취소’, 이미 사용했으면 ‘사용 완료’를 표시한다. 코드 미설정은 ‘가게에서 사용을 준비 중이에요’. 발급 수량 소진은 신규 발급만 막고 이미 받은 유효 쿠폰의 사용을 막는 근거로 삼지 않는다.
통신 예외: 성공 응답을 못 받았다고 즉시 재사용 요청을 보내지 않는다. ‘사용 상태를 확인하고 있어요’와 내역 새로고침을 제공하고 서버 상태를 재조회한다. 오프라인에서는 사용 완료를 표시하지 않는다. 연속 클릭·다른 기기에서의 사용에도 중복 처리되지 않아야 한다.
발급 취소: 기존 웹의 쿠폰 반납 기능과 정책을 확인해 동일하게 제공한다. 취소 전 확인 창을 거치며, 성공 후 취소 내역과 반환 수량을 서버 기준으로 갱신한다. 재발급 가능 여부는 기존 DB 정책을 점검한 뒤 안내한다.
9. S06 · 마이
목적과 진입: 저장한 장소와 코스를 다시 찾고 생활권을 관리한다. 하단 마이 탭에서 진입한다.
위에서 아래 순서: 인사·계정 상태 → 단골 가게·코스 수 → 저장한 가게 → 저장한 코스 → 관심 동네 변경 → 내 쿠폰함 → 계정 관리.
동작: 비로그인은 로그인 안내를 표시하며 개인 목록을 불러오지 않는다. 로그인 후 저장 목록과 수를 조회한다. 가게·코스 선택은 각 상세로 이동한다. 관심 동네 변경은 오늘·지도·혜택 탐색 범위에 반영한다.
예외와 완료 기준: 빈 목록에는 ‘동네 둘러보기’와 ‘추천 코스 보기’를 제공한다. 계정 변경·로그아웃 시 이전 계정의 개인 데이터를 화면과 기기 캐시에서 분리한다. 비공개·종료 항목도 저장 해제할 수 있어야 한다.
10. 보조 화면과 공통 규칙
동네지도: 실제 지도 공급자는 미정이다. 지도·가게 목록, 카테고리·혜택 여부 필터, 가게 상세 연결을 설계한다. 위치 권한 거부 시 선택 동네 중심으로 표시한다. 좌표 미확보 가게는 주소 기반 목록에서 접근 가능하게 한다. 시안은 가상 핀 하나로 연결 관계만 보여준다.
혜택: 공개·발급 가능한 쿠폰 목록과 내 쿠폰함 진입을 분리한다. 쿠폰 카드는 가게·혜택·주요 조건을 보여주고 상세에서 발급한다. 비로그인도 목록은 볼 수 있다.
공통 UI: 주요 터치 영역은 최소 44×44 기준으로 설계하고 글자 확대를 지원한다. 본문은 15–16px 수준을 기준으로 한다. 상태를 색상만으로 구분하지 않는다. 제목·버튼에는 접근성 이름을 제공하고 모달의 초점 이동·닫기·뒤로 동작을 관리한다.
로딩·빈 화면·오류를 구분한다. 요청 중에는 중복 버튼 동작을 막고, 실패 시 입력과 현재 위치를 보존한다. 하단 고정 버튼과 메뉴가 내용을 가리지 않도록 안전 여백과 스크롤 영역을 확보한다.
11. 기존 데이터와 추가 설계의 연결
기존 활용: 가게 공개 프로필·미니홈, 쿠폰 정의와 발급 내역, 승인된 로컬 스토리, Supabase 계정. 기존 공개 조회와 쿠폰 처리 경로를 앱용으로 안전하게 연결할 수 있는지 검토한다.
추가 설계: 관심 동네 설정, 사용자별 단골 가게, 코스 및 장소 순서, 사용자별 저장 코스, 홈 추천 편성. 추천 편성·코스 관리 화면이 운영 웹에도 필요하다. 스탬프와 푸시 데이터는 후속 범위이다.
확인할 권한: 공개 데이터와 회원 개인 데이터를 분리한다. 모든 로그인 역할이 주민 기능을 사용할지 정책을 정하고, 사장님·크리에이터 역할과 충돌하지 않게 한다. 서비스 관리자 키를 앱에 배포하지 않는다.

12. 검토 순서와 다음 산출물
이번 검토: 첫 화면에서 가볼 곳을 쉽게 찾는지, 가게 상세에서 혜택 조건을 충분히 알 수 있는지, 매장 직원이 쿠폰을 실수 없이 사용할 수 있는지, 단골·코스 저장이 재방문 이유가 되는지 확인한다.
다음 작업: 현재 회원·가게·쿠폰 스키마와 RLS 점검 → 추가 테이블·공개 조회 범위 설계 → 운영 웹의 코스·추천 편성 요구사항 정리 → 앱 기술 및 출시 플랫폼 선택 → 실제 데이터 연결 계획 작성.
